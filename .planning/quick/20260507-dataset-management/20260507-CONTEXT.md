# Quick Task 20260507: Dataset Management - Context

**Gathered:** 2026-05-07
**Status:** Ready for planning

<domain>
## Task Boundary

Extend the GenAI Teachable Machine dataset concept so users can create their own image datasets, fill them with images, tag each image as exactly one of Training or Test, and persist those datasets inside the project ZIP.

Access must be simple from the top AppBar via a `DataExplorer` button next to `Open` and `Save`.

</domain>

<decisions>
## Implementation Decisions

### Dataset Persistence
- User-created datasets are stored only inside the project ZIP.
- No standalone dataset export/import format in this quick task.
- Managed datasets should be saved with the project ZIP.

### DataExplorer Surface
- The DataExplorer button should open the existing dataset view concept and extend it with creation/management functions.
- Do not create a separate admin app or separate route.

### Image Roles
- Each dataset image has exactly one role: `training` or `test`.
- UI may show `Training` / `Test`, but serialized values should stay stable lowercase.

### Image Sources
- Reuse the same acquisition patterns as class samples:
  - Upload from local files.
  - Webcam capture.
  - OpenVerse search/import.

### Agent Discretion
- Use a pragmatic v1 scope that delivers project-owned dataset creation, image management, split tagging, persistence, and availability through the existing dataset pickers.
- Keep OpenVerse attribution/license/filter UI out of the student-facing v1 flow.
- Prefer implementation patterns already used by `Classification`, `DatasetPicker`, `DatasetTestPicker`, `ModelSaver`, and `ModelLoader`.

</decisions>

<specifics>
## Specific Ideas

- Add a top-level `DataExplorer` button near `Open` and `Save`.
- Persist dataset manifests and PNG images inside the project ZIP.
- Include user-created dataset images in training dataset selection and test dataset selection so tagged images can be reused.

</specifics>
