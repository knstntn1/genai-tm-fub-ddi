# Quick Plan 20260507: Dataset Management

## Execution Slices

This is one quick task, but it should execute as three contained slices:

1. Domain and persistence.
2. DataExplorer UI and acquisition.
3. Picker contract integration.

Commit each slice atomically.

## Task 1: Project Dataset State And ZIP Persistence

**files**

- `src/state.ts`
- `src/util/projectDatasets.ts`
- `src/util/projectDatasets.test.ts`
- `src/workflow/ImageWorkspace/saver.ts`
- `src/workflow/ImageWorkspace/loader.ts`

**action**

Add project-owned dataset types and a Jotai atom. Implement pure helpers to create datasets, add/remove images, update split tags, serialize datasets into a ZIP manifest plus PNG payloads, and load them back into canvases. Wire `ModelSaver` and `ModelLoader` so project datasets are always saved in and loaded from the project ZIP while remaining backward-compatible with ZIPs that do not contain dataset metadata.

**verify**

- Unit tests cover split validation, ZIP round-trip, and empty/backward-compatible load.
- Existing save/load behavior still compiles.

**done**

- Project datasets survive save/load without changing classifier class samples.

**action**

Add a DataExplorer dialog opened from the AppBar. The dialog lists project datasets, supports creating/deleting datasets, shows image grids, allows each image to be tagged as exactly Training or Test, and adds images through upload, webcam capture, and OpenVerse search using the existing import/capture boundaries. Add locale keys for all classroom-facing DataExplorer labels and errors; keep the AppBar label literal `DataExplorer`.

**verify**

- Component tests cover opening from AppBar, creating a dataset, upload-driven image addition, split toggle, and deletion.
- OpenVerse failure keeps the dialog recoverable without mutating dataset images.

**done**

- Users can manage project-owned datasets from the top of the app.

## Task 3: Existing Dataset Picker Integration

**files**

- `src/components/DatasetPicker/DatasetPicker.tsx`
- `src/components/DatasetTestPicker/DatasetTestPicker.tsx`
- `src/components/DatasetPicker/DatasetCategoryList.tsx`
- `src/components/DatasetTestPicker/DatasetTestCategoryList.tsx`
- `src/components/DatasetPicker/DatasetCategory.tsx`
- `src/components/DatasetPicker/DatasetItem.tsx`
- `src/components/DatasetPicker/ImageTile.tsx`
- `src/components/DatasetTestPicker/DatasetTestPicker.test.tsx`
- `src/util/datasetLoader.ts`
- `src/util/projectDatasets.ts`

**action**

Expose managed dataset images to the existing dataset picker surfaces through an explicit mixed selection contract:

- Remote catalog selections stay URL-backed and continue through `loadDatasetImagesInParallel`.
- Project-owned selections are canvas-backed and bypass remote URL loading.
- `DatasetPicker` must return selected managed training canvases directly alongside remote-loaded canvases.
- `DatasetTestPicker` must support canvas-backed managed test image selection. For callers that need `onImageUrlSelected(url)`, provide a generated `canvas.toDataURL()` value for project-owned images rather than a remote URL.

Training pickers should include images tagged `training`; test pickers should include images tagged `test`. Reuse the current remote dataset layout where practical and keep remote catalog datasets working.

**verify**

- Tests prove managed training images can be selected into class training samples.
- Tests prove managed test images can be selected as stable test inputs through `onImageSelected`, `onImageUrlSelected`, and both callbacks together.
- Tests prove remote dataset URL selections still work.

**done**

- User-created datasets are usable through the existing dataset workflows.
