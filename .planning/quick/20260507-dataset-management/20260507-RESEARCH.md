# Quick Research: Dataset Management Extension

**Researched:** 2026-05-07
**Scope:** User-created image datasets, Training/Test tagging, project ZIP persistence, and DataExplorer entry point
**Confidence:** MEDIUM-HIGH

## Summary

The existing app has two different concepts that matter here: class training samples in `classState`, and a read-only remote dataset catalog loaded from `https://store.gen-ai.fi/tm/datasets/datasets.json`. [VERIFIED: `src/state.ts:6-14`, `src/state.ts:36`, `src/util/datasets.ts:1-32`] The requested feature should add a third concept: project-owned datasets with image entries and an exactly-one `Training` or `Test` split tag. [ASSUMED: product semantics from task request]

Primary recommendation: implement a project-scoped `datasetState` with a typed `ProjectDataset` model, reuse the existing image acquisition boundaries, and persist it as an extra JSON manifest plus image files inside the project ZIP rather than merging it into `IClassification.samples`. [VERIFIED: `src/workflow/ClassEntry/Classification.tsx:112-127`, `src/workflow/ClassEntry/Classification.tsx:227-239`, `src/workflow/ClassEntry/Classification.tsx:296-335`; ASSUMED: recommended architecture]

[VERIFIED: `node_modules/@genai-fi/classifier/dist/ClassifierApp.js:2424-2478`, `node_modules/@genai-fi/classifier/dist/ClassifierApp.js:2480-2576`]

## Recommended Data Model

```ts
export type DatasetSplit = 'training' | 'test';

export interface ProjectDatasetImage {
    id: string;
    split: DatasetSplit; // exactly one of training/test
    data: HTMLCanvasElement;
    source?: 'upload' | 'webcam' | 'openverse';
}

export interface ProjectDataset {
    id: string;
    name: string;
    images: ProjectDatasetImage[];
}
```

This shape keeps the split tag on the image, which enforces exactly one Training/Test assignment without maintaining two arrays that can drift. [ASSUMED] Store `source` only for internal/debug use; keep OpenVerse license/attribution UI out of v1 per AGENTS.md. [VERIFIED: `AGENTS.md`; ASSUMED: optional internal field]

## Persistence Slice

Use `jszip`, already installed in the project, to augment the existing classifier ZIP. [VERIFIED: `package.json:25`, local `node_modules/jszip/package.json` version `3.10.1`]

Suggested ZIP layout:

```text
project-datasets/
  manifest.json
  images/
    {datasetId}_{imageId}.png
```

Manifest shape:

```json
{
  "version": 1,
  "datasets": [
    {
      "id": "ds_...",
      "name": "Meine Daten",
      "images": [
        {
          "id": "img_...",
          "split": "training",
          "path": "project-datasets/images/ds_..._img_....png",
          "source": "upload"
        }
      ]
    }
  ]
}
```

Do not persist these images in `classState.samples` unless the user explicitly imports from a managed dataset into a class. [ASSUMED] This avoids changing training semantics and keeps dataset management independent from the classifier's current class-sample lifecycle. [VERIFIED: `src/util/TeachableModel.tsx` and `.planning/codebase/ARCHITECTURE.md` show training consumes `classState`; ASSUMED: design conclusion]

## Pitfalls

- Do not reuse `src/util/datasets.ts` for project datasets. Its `Dataset` type stores translation keys and remote URLs, and `DATASETS` is an in-memory remote cache. [VERIFIED: `src/util/datasets.ts:6-31`]
- Do not store remote OpenVerse URLs as dataset image payloads if the requirement says datasets live only inside the project ZIP. Convert to readable canvas/PNG immediately. [VERIFIED: `src/util/openverseImageImport.ts:149-170`, `src/util/openverseImageImport.ts:194-213`; ASSUMED: requirement interpretation]
- Do not mutate `classState` when adding images to a managed dataset. Class samples drive training and save/load today; dataset management should not silently change the classifier. [VERIFIED: `src/state.ts:36`, `src/util/TeachableModel.tsx`; ASSUMED: product behavior]
- Avoid unbounded parallel image conversion. The existing dataset loader has a known concern: it starts one load per selected image. [VERIFIED: `.planning/codebase/CONCERNS.md`, `src/util/datasetLoader.ts:32-51`]
- Preserve stale async guards from OpenVerse. A late import must not append to a deleted or changed target dataset. [VERIFIED: `src/workflow/ClassEntry/Classification.tsx:296-335`; ASSUMED: apply same pattern]
- Save/load must be backward compatible with ZIPs that do not have `project-datasets/manifest.json`. [ASSUMED]
- The Save dialog has a "save samples" checkbox; decide whether managed datasets are always saved or tied to that checkbox. Given the task says "store datasets only inside the project ZIP", default should be always save datasets when saving a project. [VERIFIED: `src/workflow/ImageWorkspace/SaveDialog.tsx:16-57`; ASSUMED: product recommendation]
