# Phase 2 — UI Design Contract

> Visual and interaction contract for the student-facing, class-scoped OpenVerse search UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 2 delivers a reusable OpenVerse search dialog/component that lets a student search, browse image-only results, and activate a selected result through `onUseImage`. It does not add the class-card entry point, import remote images into canvas samples, or mutate class sample state; those remain Phase 3 responsibilities.

## Design Goals

| Goal | Contract |
|------|----------|
| Classroom simplicity | Keep the dialog compact, image-first, and free of metadata, provenance, license, creator, source, and advanced filter UI. |
| Class confidence | The dialog header must name the current class so the student understands the search is scoped to that class. |
| Explicit control | The search field submits only through a visible submit button or Enter while the field is focused; no search-as-you-type behavior. |
| Reusable integration boundary | Result activation calls neutral `onUseImage(result)` and communicates only selection intent, not import success. |
| Recoverable failures | Loading, empty, retryable error, rate-limit, and failed-use states must be visible and concise in German. |

## Spacing Scale

Declared values use the existing app's rem-friendly spacing while resolving to multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, focus outline offset, image overlay inset |
| sm | 8px | Control gaps, grid gutters, dialog-title icon gap |
| md | 16px | Dialog content padding, state panel padding, form row spacing |
| lg | 24px | Dialog actions padding, larger state spacing |
| xl | 32px | Top/bottom empty-state breathing room |
| 2xl | 48px | Minimum state block height when no results are present |
| 3xl | 64px | Maximum major vertical gap; rarely used in this compact dialog |

Exceptions: image result tiles may use stable square dimensions (`96px` minimum target tile, responsive up to `140px`) and controls must keep at least `44px` touch target height/width for icon or image activation affordances.

## Typography

Use exactly these text sizes in the component unless Material UI internals require inherited button sizing.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading | 18px | 600 | 1.2 |
| Button / Overlay | 14px | 600 | 1.2 |

The dialog title uses Heading. Search input, state text, and pagination context use Body or Label. The overlay action `Dieses Bild nutzen` uses Button / Overlay and must remain readable over busy thumbnails.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Dialog paper, form background, state panels |
| Secondary (30%) | `#dfe5e8` / `workspaceBg` | Surrounding app backdrop, scroll area contrast, subdued separators |
| Accent (10%) | `#008297` / `primary` | Submit button, focus outline, hover/focus tile border, pagination action, loading indicator |
| Destructive | `#e03838` | Destructive actions only; none are introduced in Phase 2 |

Accent reserved for: search submit button, active/focused result tile border, `Mehr Ergebnisse`, loading/progress indicators, and inline retry action. Do not use accent for metadata, decorative backgrounds, or every image tile at rest.

State colors: use MUI `Alert` severity styling for retryable errors and rate-limit messages. Empty state uses neutral text on white or `bgSubdued1` (`#e8f0fe`) only when it needs a visible panel.

## Layout Contract

| Area | Contract |
|------|----------|
| Dialog | MUI `Dialog` with compact paper, `fullWidth`, max width `700px`, max height `80vh`, and internal scrolling in `DialogContent`. |
| Header | `DialogTitle` with class-scoped title, close `IconButton` on the right, and no marketing/explanatory text. Title pattern: `OpenVerse: {className}`. |
| Search row | One `TextField` and one explicit `Button` in a single row on desktop/tablet. On narrow screens, stack field above button at `100%` width. |
| Results | CSS grid of square image-only tiles. Use `object-fit: cover`; no visible title, license, attribution, creator, source, dimensions, or URL. |
| Actions | Result action appears as an overlay on hover, focus-within, and tap/touch activation state. At rest, the tile is image-only. |
| Pagination | `Mehr Ergebnisse` appears below the grid when `page < pageCount`; it appends results and preserves current scroll position as much as practical. |
| Footer | No persistent footer is required unless needed for close/cancel. Close remains available from the title bar. |

Responsive grid: 2 columns below `480px`, 3 columns from `480px`, 4 columns from `700px`, and never fewer than `96px` tile width. Maintain square aspect ratio with `aspect-ratio: 1 / 1` so loading text, overlays, and images do not shift layout.

## Controls And States

| State / Control | Visual Contract | Interaction Contract |
|-----------------|-----------------|----------------------|
| Initial | Empty search field and neutral prompt text. No results grid until a search is submitted. | Submit disabled for trimmed empty query. Enter in the field submits when non-empty. |
| Searching | Preserve the submitted term in the field; show `CircularProgress` or `LinearProgress` with `Suche Bilder...`. | Disable duplicate submit for the same pending request; close remains available. Abort or ignore stale results on close/new query. |
| Results | Image-only grid. Each tile has a stable square box and lazy-safe loading presentation. | Mouse hover reveals overlay; keyboard focus reveals overlay; Enter/Space triggers `onUseImage(result)`. |
| Empty results | Neutral state in the content area: `Keine Bilder gefunden.` plus next step. | This is rendered for successful `results: []`; do not show error styling. |
| Retryable error | Error alert with short problem and `Erneut versuchen`. | Retry uses the same submitted query, page, and class context. |
| Rate limit | Warning alert with short rate-limit message and `Später erneut versuchen`. | If `retryAfter` exists, implementation may respect it, but the UI must stay recoverable and not clear the query. |
| More results | `Mehr Ergebnisse` button below the grid. | Fetches next page and appends; disabled while that page is loading. |
| Failed use | Local result-level recoverable state if `onUseImage` rejects in tests/future integration: keep the tile in place and show concise failure text without claiming import success. | Leave the result usable for retry unless parent explicitly disables it. |
| Close | Close icon in title bar. | Returns focus to the opener in Phase 3 integration; Phase 2 component must expose `onClose`. |

Implementation notes: use `searchOpenVerseImages` from `src/util/openverse.ts`; map `OpenVerseSearchError.code` to UI states. `empty-query` should normally be prevented by disabled submit, but if reached, show inline field helper text rather than a dialog-level error.

## Accessibility Contract

| Requirement | Contract |
|-------------|----------|
| Dialog semantics | Use MUI `Dialog`, `DialogTitle`, and accessible close button. The title text must include the class name. |
| Search input | Provide a visible German label such as `Suchbegriff`; do not rely only on placeholder text. |
| Submit | Button text must be visible and specific: `Bilder suchen`. |
| Result tiles | Each tile is a real `button` or has equivalent button semantics, `tabIndex=0`, keyboard activation, and a German accessible name using available hidden title only for aria, not visible metadata. |
| Keyboard | Tab order: close, search field, submit, result tiles, `Mehr Ergebnisse`, retry where present. Enter/Space on focused tiles calls the same handler as click/tap. |
| Focus visibility | Focused result tile uses primary border or outline with at least 2px visible contrast and reveals the overlay. |
| Touch | First tap on a tile must make the `Dieses Bild nutzen` affordance available and/or activate through an always reachable overlay button. Touch users must not depend on hover. |
| Images | Thumbnail `alt` may use the normalized title for screen readers, but title must not be visible in the grid. Empty title falls back to `OpenVerse Bild`. |
| Loading | Announce search result state changes through normal visible text and an `aria-live="polite"` container for loading/empty/error messages. |

## Component API Contract

The Phase 2 UI should be reusable by Phase 3 with this behavioral surface:

| Prop / Event | Contract |
|--------------|----------|
| `open` | Controls dialog visibility. |
| `className` | Required display string for title and class context. |
| `onClose` | Called when the dialog closes; must not clear parent class state. |
| `onUseImage` | Called with selected `OpenVerseImageResult`; does not imply import success. May be sync or async. |
| Search client | Default implementation uses `searchOpenVerseImages`; tests may inject or mock the client. |

Do not expose props for advanced OpenVerse filters in Phase 2.

## Visual Constraints

- Use existing MUI `Dialog`, `TextField`, `IconButton`, `Alert`, `CircularProgress`/`LinearProgress`, and existing `Button` from `src/components/button/Button.tsx`.
- Use CSS modules under the Phase 2 workflow component folder; no global CSS additions unless unavoidable.
- Keep cards and tiles at `5px` to `6px` border radius to match existing sample and dialog patterns.
- Result grid must remain image-only at rest. No captions, badges, source names, license chips, creator text, dimensions, or filter chips.
- Avoid decorative gradients, hero treatments, and landing-page composition. This is a compact workflow tool inside the training-data experience.
- Stable tile dimensions are mandatory so overlays, failed thumbnail loads, and loading states cannot reflow the grid.

## Testable Acceptance Criteria

| Criterion | Verification |
|-----------|--------------|
| Class context visible | Rendering with class name `Klasse 1` shows a dialog title containing `Klasse 1`. |
| Explicit search | Typing a query does not call the client until `Bilder suchen` or Enter is used. |
| Empty query blocked | Whitespace-only query does not call the client and keeps the result area stable. |
| Loading state | Pending search shows `Suche Bilder...` and disables duplicate submit. |
| Empty results | Successful response with `results: []` shows `Keine Bilder gefunden.` and no error alert. |
| Image-only grid | Result state renders image tiles and `Dieses Bild nutzen` overlay, with no visible title/license/creator/source text. |
| Hover/focus/touch equivalent | Overlay action is available on hover and focus; keyboard Enter/Space calls `onUseImage` with the selected result. |
| Retryable error | Network/http/invalid-response errors show German retry text and `Erneut versuchen`; retry reuses the submitted term. |
| Rate limit | `rate-limited` shows the rate-limit copy and does not clear current query/results context. |
| Pagination | When `page < pageCount`, `Mehr Ergebnisse` loads the next page and appends results. |
| Phase boundary | Activating a result calls `onUseImage` and does not mutate `classState` or add samples in Phase 2 tests. |
| i18n | German copy comes from locale JSON via `useTranslation(namespace)`, not hard-coded strings in JSX except test fixtures. |

## Risks And Mitigations

| Risk | Mitigation |
|------|------------|
| Students may think selection already imported a sample in Phase 2 | Keep callback neutral (`onUseImage`) and avoid success copy that says "importiert" or "hinzugefügt". |
| Touch users cannot hover | Provide focus/touch-equivalent overlay behavior and ensure tile activation is reachable without hover. |
| OpenVerse returns valid empty arrays | Treat as empty UI state, never an error, matching Phase 1 verification. |
| Result metadata leaks into v1 UI | Preserve metadata only in the result object for future use; do not render it visibly. |
| Direct browser search reliability varies | Show retryable UI states; full live OpenVerse/CORS validation remains Phase 4. |
| Large result sets can clutter the dialog | Page with `Mehr Ergebnisse`; do not infinite-scroll automatically. |
