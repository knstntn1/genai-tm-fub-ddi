# Plan 04-01: Live Browser Validation

## Objective

Validate `TEST-05` by exercising the completed OpenVerse image-search import feature in a real local browser with live OpenVerse data.

## Tasks

1. Start the local Vite dev server.
2. Open the app in browser automation and reach the image training-data workflow.
3. Desktop validation:
   - Confirm `Bildsuche` is visible beside existing image sample actions.
   - Search a representative OpenVerse query.
   - Confirm results are image-only and do not expose license, attribution, source, creator, or advanced filters.
   - Import at least one usable result into the intended class.
   - Attempt or observe a failed-provider/import state and confirm recovery.
4. Tablet and mobile validation:
   - Confirm entry point label fit, dialog usability, result grid/action access, and no metadata/filter chrome.
5. Persistence/training validation:
   - Save or export a project containing an OpenVerse-imported sample.
   - Load or re-open that project if supported by the local UI flow.
   - Train with the imported sample included.
6. Record results in `04-VALIDATION-RESULTS.md`.
7. Create `04-VERIFICATION.md` with pass/fail against Phase 4 success criteria.
8. Update `REQUIREMENTS.md`, `ROADMAP.md`, and `STATE.md`.

## Acceptance Criteria

- `TEST-05` can be marked complete only if live validation covers real search, real import/CORS behavior, save/load or equivalent project persistence behavior, and training.
- If direct browser import cannot reliably produce a successful readable sample, Phase 4 must not hide that failure. It must document the failure and recommend v2 proxy/cache/disable-switch work.

## Verification Commands

- `npm run lint`
- `npm run build`

Browser checks are manual/automated-observation evidence and are recorded in the validation results document.
