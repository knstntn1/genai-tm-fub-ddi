# Phase 3 — UI Design Contract

> Visual and interaction contract for integrating OpenVerse image search into the existing training workflow. Generated by gsd-ui-researcher, pending gsd-ui-checker verification.

---

## Scope

Phase 3 adds the OpenVerse entry point to each image class card and wires selected OpenVerse results into the existing class sample state after successful remote-image import. It must not add OpenVerse controls to speech/audio workflows, must not expose license/attribution/filter UI, and must keep failed or stale imports recoverable without mutating class state.

## Design Goals

| Goal | Contract |
|------|----------|
| Familiar sample source | Add OpenVerse as the third class-card action beside Webcam and Upload, using the same `VerticalButton` treatment and sample-list rhythm. |
| Class-scoped confidence | Opening the dialog from a class card must pass the current class label to the Phase 2 dialog title: `OpenVerse: {{className}}`. |
| Import certainty | A selected result becomes visible in the intended class only after `importOpenVerseImage` returns a readable canvas. |
| Recoverable failure | Failed import keeps the dialog open, shows concise German failure copy, leaves all class samples unchanged, and allows retry. |
| Image-only boundary | `Bildsuche` is available only in image workflows; speech/audio cards keep their current microphone/upload behavior unchanged. |
| Deferred visual validation | Carry the Phase 2 browser visual/touch check into the integrated workflow once the dialog is reachable from the class card. |

## Spacing Scale

Declared values use the existing app spacing while resolving to multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, focus outline offset, result failure inset |
| sm | 8px | Button row gaps, sample-list gutters, dialog overlay padding |
| md | 16px | Class-card action margins, dialog content gaps, import state padding |
| lg | 24px | Dialog title horizontal padding, larger state spacing |
| xl | 32px | Reserved for rare class-card breathing room; avoid inside compact action row |
| 2xl | 48px | Minimum dialog state block height |
| 3xl | 64px | Not used in Phase 3 workflow integration |

Exceptions: existing sample thumbnails and class-card action items use the established `58px` visual size. Image/search icon-only affordances, if any are introduced, must keep at least `44px` touch target height/width. Existing CSS radii of `5px` to `6px` remain allowed for samples, tiles, and compact workflow controls.

## Typography

Use exactly these text sizes for new Phase 3 UI unless inherited Material UI button internals already match the existing button system.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading | 18px | 600 | 1.2 |
| Button / Overlay | 14px | 600 | 1.2 |

`Bildsuche` uses the existing `VerticalButton` typography and must not wrap awkwardly inside the class-card action item. Import failure and pending text use Body or Button / Overlay according to their host component.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Class-card action button surfaces, dialog paper, form background |
| Secondary (30%) | `#dfe5e8` / `workspaceBg`; `#e8f0fe` subdued panel | Workflow background, drop hints, neutral state panels |
| Accent (10%) | `#008297` / `primary` | `Bildsuche` focus/hover outline, dialog submit, result focus border, loading indicators, retry action |
| Destructive | `#e03838` | Existing delete/disable destructive UI only; Phase 3 introduces no new destructive action |

Accent reserved for: the `Bildsuche` action affordance when focused/hovered, existing Phase 2 search submit, result focus/hover border, progress indicators, `Mehr Ergebnisse`, and retry actions. Do not use accent as a decorative fill for every sample tile or for metadata badges.

Import failure uses MUI `Alert` error styling or the Phase 2 failed-use overlay pattern. Import pending can use `CircularProgress` with accent color and must not change the class sample count visually until success.

## Layout Contract

Primary focal point: the existing class-card action row, with `Bildsuche` presented as the third peer action beside Webcam/Upload.

| Area | Contract |
|------|----------|
| Class-card action placement | Insert a third `<li className={style.sample}>` in the inactive image card action row, after Webcam and Upload when Upload is enabled. If Upload is disabled by variant config, `Bildsuche` appears after Webcam. |
| Action component | Use existing `VerticalButton` with `variant="outlined"`, German label `Bildsuche`, and an image/search Material UI icon such as `ImageSearchIcon`. Do not create a separate card, banner, toolbar, or floating button. |
| Image-only gating | Render `Bildsuche` only when `modelVariant !== 'speech'`. Audio cards must not reserve blank space for it. |
| Dialog trigger | Clicking `Bildsuche` opens the existing `OpenVerseSearchDialog` from the same class-card component. The dialog receives the current class label from that card. |
| Sample insertion | On successful import, insert `{ data: canvas, id: '' }` at the front of the target class samples, matching webcam/upload ordering. Set imported canvas visual size to `58px` by `58px` before state mutation. |
| Active webcam state | The `Bildsuche` action is hidden while the class is expanded for webcam capture, matching current Webcam/Upload inactive-row behavior. |
| Disabled class | Disabled classes keep the existing disabled-card visual treatment. `Bildsuche` must be non-interactive because the disabled class wrapper blocks pointer interaction. |
| Sample list | The imported sample appears as a normal `Sample` tile in the existing horizontal/wrapping sample list. No OpenVerse badge, source text, title, license, or attribution appears on the tile. |

Do not change Phase 2 dialog layout except where integration requires import pending/failure behavior. The dialog keeps the compact `700px` max-width, `80vh` height, sticky search form, 2/3/4 responsive result grid, and image-only tile rest state.

## Controls And States

| State / Control | Visual Contract | Interaction Contract |
|-----------------|-----------------|----------------------|
| `Bildsuche` ready | Outlined `VerticalButton` in the sample action row with `ImageSearchIcon` or equivalent and label `Bildsuche`. | Click opens the class-scoped dialog. Keyboard focus and Enter/Space activate through native button behavior. |
| Dialog open | Phase 2 dialog title includes the current class name. Search field and results behave as already specified in Phase 2. | Focus returns to the `Bildsuche` opener after close where practical. |
| Import pending | The selected result is disabled through Phase 2 `pendingUseIds`; show pending cursor/progress on that tile. No success copy appears yet. | Duplicate activation of the same result is blocked. Other class state remains unchanged until success. Close may remain available; stale completion must be ignored if target class is invalid. |
| Import success | Dialog closes or leaves the result no longer pending only after the canvas sample is inserted; the target class count and first sample tile update immediately. | Insert at the front of the originally targeted class only. Other classes are unchanged. |
| Import failure | Keep dialog open and show `Dieses Bild konnte nicht genutzt werden. Bitte erneut versuchen.` on the result or in a compact alert. | Failed import can be retried. Class state is unchanged. The search query and visible results remain intact. |
| Stale import | No visible success or mutation. If feedback is needed, reuse failed-import copy without blaming the student. | If the class index no longer exists, the class label no longer matches the captured target, or request identity is stale, discard the imported canvas. |
| Search failures | Use existing Phase 2 loading, empty, retryable error, rate-limit, and pagination states. | Search errors never mutate samples and never close the dialog automatically. |
| Audio workflow | No `Bildsuche` control appears. | Speech/audio capture/upload/recorder behavior remains unchanged. |

## Accessibility Contract

| Requirement | Contract |
|-------------|----------|
| Action semantics | `Bildsuche` is a real button through `VerticalButton`; accessible name is the visible German label. |
| Icon | Use a Material UI image/search icon, decorative to screen readers unless the button component requires icon text. The label carries the name. |
| Keyboard | Tab order within a class card keeps Webcam, Upload, then Bildsuche before sample tiles when those controls are visible. Enter/Space opens the dialog. |
| Dialog semantics | Use existing Phase 2 MUI `Dialog`, `DialogTitle`, accessible close button, visible search label, and result buttons. |
| Class context | Dialog title includes the class label for sighted users and screen readers. |
| Import status | Pending/failure status is visible and announced through existing Phase 2 `aria-live="polite"`/`role="status"` regions where practical. |
| Focus recovery | Closing the dialog should return focus to the originating `Bildsuche` button if it still exists. |
| Touch | `Bildsuche` keeps a minimum practical touch target equivalent to existing class-card actions, and the result action remains touch-reachable per Phase 2. |
| No hidden metadata dependency | Accessible image names may use normalized OpenVerse titles as alt/aria text, but metadata must not become visible UI. |

## Copywriting Contract

German classroom-facing copy must be localized in the active variant namespace. English fallback may be direct, but German is the contract.

| Element | Copy |
|---------|------|
| Class-card action | `Bildsuche` |
| Dialog title | `OpenVerse: {{className}}` |
| Search primary CTA | `Bilder suchen` |
| Result action | `Dieses Bild nutzen` |
| Import pending accessible/status copy | `Bild wird hinzugefügt...` |
| Import failure | `Dieses Bild konnte nicht genutzt werden. Bitte erneut versuchen.` |
| Retry action | `Erneut versuchen` |
| Empty state heading | `Keine Bilder gefunden.` |
| Empty state body | `Versuche einen anderen Suchbegriff.` |
| Error state | `Die Bildsuche hat nicht geklappt. Bitte erneut versuchen.` |
| Rate-limit state | `Gerade sind zu viele Suchanfragen aktiv. Versuche es gleich noch einmal.` |
| Destructive confirmation | none |

Copy constraints: do not show OpenVerse license, attribution, creator, source, provenance, dimensions, mature-content controls, or advanced filter labels in v1. Do not show a success toast that says an image was added before the sample is actually inserted.

## Component Integration Contract

| Component / API | Contract |
|-----------------|----------|
| `Classification` | Owns `showOpenVerseSearch`, selected import pending/failure flow, and renders `Bildsuche` only for image workflows. |
| `OpenVerseSearchDialog` | Reused from Phase 2. Receives `open`, `className`, `onClose`, and async `onUseImage(result)`. No class state mutation is added inside the dialog. |
| `importOpenVerseImage` | Called from the class-card integration handler. Must resolve to a readable bounded `HTMLCanvasElement` before any sample mutation. |
| `setData` | Called exactly once per successful import for the captured target class, inserting the new sample at the front. |
| Class identity guard | Capture class index, class label, and request/import identity when selection starts; verify the target class still exists and still represents the intended class before mutating. |
| Existing sample shape | Use `{ data: canvas, id: '' }`, matching webcam/upload/dataset samples. No OpenVerse-specific sample shape is introduced in Phase 3. |
| Existing sample tools | Delete, preview, move-to-class, save/load preparation, and training should operate on imported samples as normal canvas samples. |

## Visual Constraints

- Keep the class card visually balanced with three compact actions; do not add explanatory text below `Bildsuche`.
- Do not introduce nested cards, banners, hero treatments, tooltips that teach OpenVerse, or metadata chips.
- Use existing `classification.module.css` layout primitives where possible: `.sample`, `.samplelistSmall`, `.samplelistLarge`, `.buttoncontainer`, and current `58px` sample sizing conventions.
- The `Bildsuche` label must fit inside the same button footprint as `Webcam` and `Upload`; if the existing vertical button width is tight, adjust only the action-row/button sizing enough to avoid text clipping across German and fallback locales.
- Preserve Phase 2 dialog visual requirements: compact paper, stable square tiles, image-only grid at rest, visible focus outline, hover/focus/touch access to `Dieses Bild nutzen`, and no metadata/filter chrome.
- Address the Phase 2 UI review warning opportunistically if touching dialog CSS: define local semantic overlay variables or token comments for the black translucent thumbnail overlays instead of adding more hardcoded contrast colors.

## Testable Acceptance Criteria

| Criterion | Verification |
|-----------|--------------|
| Image entry point visible | Rendering an image workflow class card shows Webcam, Upload when enabled, and `Bildsuche` in the action row. |
| Audio entry point absent | Rendering a speech/audio workflow class card does not show `Bildsuche` and does not reserve empty action space for it. |
| Correct icon and label | The OpenVerse action uses a Material UI image/search icon and visible text `Bildsuche`. |
| Class-scoped dialog | Clicking `Bildsuche` opens `OpenVerseSearchDialog` with a title containing the current class label. |
| Successful import mutates target only | Selecting a result, with `importOpenVerseImage` mocked to resolve a canvas, inserts one normal sample at the front of the intended class and leaves other classes unchanged. |
| Failed import is recoverable | Mocked importer rejection shows `Dieses Bild konnte nicht genutzt werden. Bitte erneut versuchen.`, keeps the dialog open, preserves results/query, and leaves all class sample arrays unchanged. |
| Duplicate pending import blocked | Repeated activation of the same pending result does not add duplicate samples. |
| Stale target discarded | If the target class disappears, changes identity, or a newer import supersedes the pending one, the late result does not mutate any class. |
| Normal sample behavior | Imported sample can be previewed, deleted, and moved through existing sample modal behavior because it has the same canvas sample shape. |
| Count and ordering | The class sample count updates immediately after success and the imported tile appears before previous samples. |
| Existing boundaries preserved | Component/code scans show no visible license, creator, source, attribution, advanced filter, mature-control, or provenance UI. |
| Deferred browser validation carried | Phase 3/4 verification includes real browser desktop/tablet/mobile checks for the integrated `Bildsuche` opener and Phase 2 dialog hover/focus/touch overlay. |

## Risks And Mitigations

| Risk | Mitigation |
|------|------------|
| Student adds an image to the wrong class after slow import | Capture target class identity and discard stale completions before calling `setData`. |
| Remote image import fails after the student selected a useful result | Keep dialog and results visible, show short recoverable failure copy, and allow retry. |
| New action crowds the class-card sample row | Use the same `VerticalButton` and `.sample` sizing rhythm; verify German label fit in browser. |
| Audio workflow accidentally exposes image search | Guard rendering with `modelVariant !== 'speech'` and add a regression test. |
| Imported samples become special cases | Store the exact normal sample shape `{ data: canvas, id: '' }` and use existing preview/delete/move paths. |
| Browser/touch polish remains unverified | Carry the Phase 2 human visual/touch check into integrated workflow verification and Phase 4 live validation. |
